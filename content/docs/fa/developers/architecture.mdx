## یک باینری، دو حالت دسکتاپ [#one-binary-two-desktop-modes]

```text
NuggetVPN                  GUI, running as the user
NuggetVPN --core-service   Privileged tunnel service
```

رابط کاربری گرافیکی یک نسخه دیگر از خودش را از طریق جریان تأیید پلتفرم راه‌اندازی می‌کند: `osascript` روی macOS، `pkexec` روی Linux، یا UAC روی Windows. بنابراین هر دو طرف از همان نسخه برنامه استفاده می‌کنند.

```text
React + Wails UI  ←→  Authenticated socket  ←→  Core service
    user                  JSON lines              admin
                                              TUN, DNS, routing
                                              embedded engines
```

سرویس ممتاز کتابخانه‌های هسته‌ای را درون فرآیند فراخوانی می‌کند. گزارش‌ها، وضعیت اتصال، شمارنده‌های بایت و فهرست اتصال زنده از همان سوکت برمی‌گردند. خروج از رابط کاربری گرافیکی سرویس را خاموش می‌کند؛ سرویس همچنین فرآیند رابط کاربری گرافیکی را نظارت می‌کند تا یک خرابی سرویس را با جدول مسیرها تنها نگذارد.

## تأیید هویت سوکت [#socket-authentication]

هر اتصال سرویس ابتدا باید یک توکن ۲۵۶ بیتی برای هر جلسه ارائه دهد. رابط کاربری گرافیکی آن را در یک فایل `0600` می‌نویسد، فرآیند ارتقا یافته فایل را می‌خواند و حذف می‌کند، و اتصالات غیرمجاز بدون آشکار کردن وضعیت بسته می‌شوند.

ارسال توکن از طریق فایل از انتشار آن در خط فرمان قابل خواندن برای همه در Linux جلوگیری می‌کند. تأیید هویت صریح همچنین پلتفرم‌هایی را پوشش می‌دهد که در آنها chmod و chown سوکت یونیکس حریم دسترسی مورد انتظار را اعمال نمی‌کنند.

## موتورهای توکار [#embedded-engines]

شاخهٔ داخلی TodayCore مسیر ماژول sing-box را با استفاده از دستور Go `replace` نگه‌می‌دارد. sing-box رسمی و sing-tun تحت مسیرهای ماژول جداگانه در `third_party/` قرار گرفته‌اند تا هر دو پیاده‌سازی بتوانند هم‌زیستی داشته باشند.

mihomo تنظیمات کامل Clash را مدیریت می‌کند. Xray سمت سرور اتصال را پشت هستهٔ داخلی اجرا می‌کند که TUN، DNS و مسیریابی را حفظ می‌کند. یک نقطهٔ ورودی حلقه برگشتی محافظت‌شده، انتقال Xray را مستقیماً خارج می‌کند تا از خودمسیریابی جلوگیری شود.

هیچ کنترل‌کنندهٔ هستهٔ HTTP راه‌اندازی نمی‌شود. حسابداری ترافیک و بررسی اتصال در فرآیند خوانده می‌شوند و گزینه‌های کنترل‌کننده از تنظیمات واردشدهٔ Clash حذف می‌شوند.

## نقشهٔ منبع [#source-map]

| مسیر | مسئولیت |
| --- | --- |
| `main.go` | نقطه ورود، رابط گرافیکی/ارسال‌دهنده سرویس، پنجره و سینی. |
| `internal/app/` | سرویس‌هایی که برای رابط کاربری ارائه شده‌اند. |
| `internal/core/` | سرویس ممتاز، کلاینت IPC و زمان‌های اجرای درون‌فرآیندی. |
| `internal/sbconfig/` | پروفایل و تنظیمات برای sing-box پیکربندی؛ کامپایل مسیرها. |
| `internal/cores/` | ترجمه پیکربندی mihomo و Xray. |
| `internal/link/` | اشتراک‌گذاری لینک، JSON sing-box و تجزیه YAML Clash. |
| `internal/remote/` | اشتراک‌ها و همگام‌سازی اختیاری پروفایل. |
| `internal/probe/` | بررسی تأخیر و ارتباط. |
| `internal/stats/`، `internal/speedtest/` | اندازه‌گیری‌های ذخیره‌شده و تست‌های سرعت. |
| `internal/plugins/` | بسته‌بندی افزونه، اعتبارسنجی، ارائه و سیاست sandbox. |
| `internal/cli/` | خط فرمان دسکتاپ و سوکت کنترل. |
| `internal/storage/`، `internal/models/` | ماندگاری و انواع مشترک. |
| `frontend/` | برنامه React، پل پشتیبان و ترجمه‌ها. |
| `Taskfile.yml`، `build/` | وظایف ساخت و بسته‌بندی. |

## Android مرز [#android-boundary]

VpnService متعلق به Android تونل را ارائه می‌دهد به جای یک فرآیند دسکتاپ با امتیاز ویژه. `internal/android` رابط را به sing-box منتقل می‌کند، سوکت‌های اصلی را خارج از VPN نگه می‌دارد و شبکه فعلی را گزارش می‌دهد. یک میزبان کوچک جاوا، کتابخانه مشترک Go را در برنامه WebView بارگذاری می‌کند.

برای اجرای پروژه به [ساختمان](/fa/docs/developers/building) و برای مرز افزونه به [امنیت پلاگین](/fa/docs/plugins/security) مراجعه کنید.
