## DNS پیش‌فرض [#default-dns]

**تنظیمات → خانه → سرور DNS** تعیین می‌کند که هنگام اتصال نام‌ها کجا رزولوشن می‌شوند. برنامه یک آدرس رزولور مانند `1.1.1.1` را می‌پذیرد.

هنگام تغییر حل‌کننده، الزامات ارائه‌دهنده خود را در نظر داشته باشید. اگر سرور متصل شد اما وب‌سایت‌ها بارگذاری نشدند، DNS یکی از تنظیماتی است که باید بررسی کنید.

## DNS برای یک قانون [#dns-for-a-rule]

قوانین دامنه در **مسیریابی** می‌توانند حل‌کننده DNS خود را انتخاب کنند. فیلد DNS قانون مقادیر زیر را می‌پذیرد:

| مقدار | حل‌کننده |
| --- | --- |
| `1.1.1.1` | یک آدرس سرور ساده DNS. |
| `tls://dns.example.com` | DNS از طریق TLS. نام میزبان نمونه را با حل‌کننده خود جایگزین کنید. |
| `https://dns.example.com/dns-query` | DNS از طریق HTTPS. از نقطه پایان واقعی حل‌کننده استفاده کنید. |
| `local` | حل نام محلی. |

این مورد وضوح را برای دامنه‌های مطابقت‌دهنده کنترل می‌کند. مقصد قانون به طور جداگانه تعیین می‌کند که اتصال حاصل چگونه هدایت شود.

## MTU [#mtu]

**تنظیمات → اتصال → MTU** بزرگترین بسته‌ای را که تونل می‌تواند حمل کند، تعیین می‌کند. راهنمای برنامه برای بیشتر لینک‌ها عدد ۹۰۰۰ را پیشنهاد می‌کند و پیشنهاد می‌دهد آن را کاهش دهید وقتی انتقال‌های بزرگ متوقف می‌شوند.

هنگام تشخیص مشکل، یک تنظیم را در هر بار تغییر دهید و همان درخواست یا انتقال را مقایسه کنید. مقدار قبلی را یادداشت کنید تا بتوانید آن را بازیابی کنید.

## TLS و مبهم‌سازی [#tls-and-obfuscation]

**تنظیمات → TLS و مبهم‌سازی** شامل TLS قطعه‌بندی، حالت ترکیبی SNI، پر کردن رکورد و جعل SNI است. این‌ها روی دست‌دهی‌ها تأثیر می‌گذارند و باید برای سرور یا نیاز شبکه‌ی شناخته‌شده انتخاب شوند.

تنظیمات قطعه‌بندی TLS و SNI برنامه برای mihomo یا Xray اعمال نمی‌شود. برای آن کنترل‌ها از هسته داخلی یا sing-box رسمی استفاده کنید. سازگاری هسته را در [core compatibility](/fa/docs/reference/cores) ببینید.
