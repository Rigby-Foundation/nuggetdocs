**مسیریابی** را باز کنید تا قوانین را به صورت نمودار بسازید یا آنها را در نمای قوانین ویرایش کنید. قوانین با اتصالات مطابقت پیدا می‌کنند و آنها را به مقصد می‌فرستند.

## مقاصد [#destinations]

| مقصد | رفتار |
| --- | --- |
| **از طریق VPN** | از سرور VPN متصل استفاده می‌کند. |
| **مستقیم** | از تونل عبور نمی‌کند و از اتصال خود شما استفاده می‌کند. |
| **مسدود** | اتصال را رد می‌کند. |
| **دور انداختن** | اتصال را بدون پاسخ دور می‌اندازد. |
| **سرور مشخص** | ترافیک مطابق را از طریق سرور پیکربندی شده دیگری ارسال می‌کند. |

<Callout type="warn" title="ترافیک مستقیم از VPNعبور می‌کند">
تنها از **مستقیم** برای ترافیکی که می‌خواهید در اتصال خودتان باشد استفاده کنید. همچنین **بقیهٔ ترافیک** را بررسی کنید: این مسیر ترافیکی که با هیچ قانونی مطابقت ندارد را تعیین می‌کند.
</Callout>

## یک قانون بسازید [#make-a-rule]

1. کنترل‌های **افزودن** را در **مسیریابی** باز کنید و یک منبع ترافیک انتخاب کنید، مانند **برنامه‌ها** یا **دامنه‌ها** .
2. برنامه، دامنه، آدرس یا مقادیر دیگر برای مطابقت را اضافه کنید.
3. در نمای گراف، از لبه راست منبع به مقصدی که می‌خواهید بکشید.
4. سفارش **ترتیب** و قانون را جایی قرار دهید که باید بررسی شود.
5. مقصد **بقیهٔ ترافیک** تأیید کنید.

منبعی بدون ورودی هیچ چیزی را مطابقت نمی‌دهد. نمودار همچنین از یادداشت‌ها پشتیبانی می‌کند و گزینه‌های بازگردانی و انجام دوباره هنگام ویرایش در دسترس هستند.

## آنچه می‌توانید مطابقت دهید [#what-you-can-match]

| منبع | مطابقت‌ها |
| --- | --- |
| **برنامه‌ها** | نام فرآیندها روی دسکتاپ، یا برنامه‌ها روی Android. |
| **دامنه‌ها** | سایت‌ها و زیر دامنه‌ها. |
| **IP / شبکه‌ها** | آدرس‌های IP و بلاک‌های CIDR. |
| **الگوی دامنه** | عبارت‌های منظم برای دامنه. |
| **درگاه‌ها** | یک پورت واحد یا یک بازه. |
| **پروتکل‌های ترافیک** | ترافیک شناسایی‌شده مانند HTTP، DNS، یا TLS. |
| **لایهٔ انتقال** | TCP یا UDP. |
| **سرویس / کشور** | دسته‌بندی‌ها و مجموعه قوانین GeoSite یا GeoIP. |
| **فهرست قواعد** | سایت‌ها یا آدرس‌ها از یک لیست قابل دانلود. |
| **ترکیبی** | چندین شرط که با AND یا OR به هم متصل شده‌اند، با گزینه NOT اختیاری. |

## اولین تطابق برنده است [#first-match-wins]

قوانین از بالا بررسی می‌شوند. اولین قانون مطابق، مسیر را تعیین می‌کند. بنابراین یک قانون برنامه بالاتر از قانون دامنه می‌تواند مسیر را قبل از بررسی قانون دامنه تعیین کند.

برای مثال، برای ارسال بیشتر ترافیک از طریق VPN اما یک برنامه خاص به صورت مستقیم:

1. یک قانون **برنامه‌ها** برای آن برنامه اضافه کنید و آن را به **مستقیم** متصل کنید.
2. آن را بالاتر از قوانین گسترده‌تر نگه دارید که ممکن است با برنامه هم مطابقت داشته باشند.
3. **بقیهٔ ترافیک** را به **از طریق VPN** متصل کنید.

از **اتصال‌های شبکه** برای بررسی اینکه کدام قانون یک درخواست را گرفته است استفاده کنید. نشانگر تطبیق قانون شمارش اتصالات مطابقت‌دهنده‌ای است که اکنون باز هستند.

## یک سرور خاص یا DNS resolver [#a-particular-server-or-dns-resolver]

اضافه کردن **سرور مشخص** برای ارسال یک قانون از طریق خروجی دیگر. اگر بعداً آن سرور حذف شود، قانون به سرور متصل بازمی‌گردد.

یک قانون دامنه همچنین می‌تواند resolver خودش را انتخاب کند. قبل از اختصاص دادن یکی، به [DNS](/fa/docs/guides/dns) مراجعه کنید.

## سازگاری هسته‌ها [#core-compatibility]

هسته داخلی از ویرایشگر مسیر کامل پشتیبانی می‌کند. Xray ترافیک سرور را مدیریت می‌کند در حالی که هسته داخلی مسیریابی را حفظ می‌کند. با mihomo، قوانین پروتکل شناسایی‌شده و لیست قوانین قالب sing-box نادیده گرفته می‌شوند و داده‌های جغرافیایی خود استفاده می‌شوند. تفاوت‌های هسته را ببینید [core differences](/fa/docs/reference/cores).

برای پیش‌تنظیمات، داده‌ها، اشتراک‌گذاری و زمان‌بندی‌های GeoIP/GeoSite، با تنظیمات مسیریابی [ادامه دهید](/fa/docs/guides/routing-setups).
