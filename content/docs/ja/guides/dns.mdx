## デフォルトDNS [#default-dns]

**設定 → ホーム → DNS サーバー** は接続中に名前が解決される場所を制御します。アプリは`1.1.1.1`のようなリゾルバアドレスを受け入れます。

リゾルバーを変更する際には、プロバイダーの要件を念頭に置いてください。サーバーには接続できるがウェブサイトが読み込まれない場合は、DNS が確認すべき設定の一つです。

## ルールのための DNS [#dns-for-a-rule]

**ルーティング** のドメインルールでは、それぞれ独自の DNS リゾルバーを選択できます。ルールの DNS フィールドには以下を入力できます:

| 値 | リゾルバー |
| --- | --- |
| `1.1.1.1` | 通常の DNS サーバーアドレス |
| `tls://dns.example.com` | DNS over TLS。例のホスト名を自分のリゾルバーに置き換えてください |
| `https://dns.example.com/dns-query` | DNS over HTTPS。リゾルバーの実際のエンドポイントを使用してください |
| `local` | ローカル名前解決 |

これは一致するドメインの解決を制御します。ルールの宛先は、生成された接続がどのようにルーティングされるかを別途決定します。

## MTU [#mtu]

**設定 → 接続 → MTU** はトンネルで送信される最大パケットサイズを設定します。アプリのガイダンスでは、ほとんどのリンクに対して9000を使用し、大きな転送が停止する場合には値を下げることを推奨しています。

問題を診断する際には、一度に1つの設定を変更し、同じリクエストや転送を比較してください。以前の値をメモしておくと、元に戻すことができます。

## TLS とオブフスケーション [#tls-and-obfuscation]

**設定 → TLS と難読化** には、TLSフラグメンテーション、混合SNIケース、レコードパディング、およびSNIスプーフィングが含まれます。これらはハンドシェイクに影響し、既知のサーバーまたはネットワーク要件に応じて選択する必要があります。

アプリのTLSフラグメンテーションおよびSNI設定は、mihomoやXrayには適用されません。それらのコントロールには、組み込みのコアまたは公式のsing-boxを使用してください。詳細は[コア互換性](/ja/docs/reference/cores)を参照してください。
