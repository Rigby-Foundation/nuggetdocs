---
title: "通信のルーティング"
description: "どのアプリやウェブサイトがVPNを使用するか、直接接続するか、またはブロックされるかを選択します。"
---

**ルーティング** を開き、ルールをグラフとして作成するか、ルール表示で編集します。ルールは接続と一致し、宛先に送信します。

## 宛先 [#destinations]

| 宛先 | 動作 |
| --- | --- |
| **VPN 経由** | 接続されたVPNサーバーを使用します。 |
| **直接** | トンネルを迂回して自分の接続を使用します。 |
| **ブロック** | 接続を拒否します。 |
| **破棄** | 接続を応答なしで破棄します。 |
| **特定のサーバー** | 一致するトラフィックを他の設定されたサーバー経由で送信します。 |

<Callout type="warn" title="直接トラフィックはVPNをバイパスします">
**直接** は、自分の接続で行いたいトラフィックにのみ使用してください。 **そのほかすべて** も確認してください。ルールに一致しないトラフィックのルートを決定します。
</Callout>

## ルールを作成する [#make-a-rule]

1. **追加** コントロールを **ルーティング** で開き、 **アプリケーション** や **ドメイン** などのトラフィックソースを選択します。
2. 一致させたいアプリ、ドメイン、アドレス、またはその他の値を追加します。
3. グラフビューで、ソースの右端から目的地までドラッグします。
4. **順序** を開き、ルールを確認すべき場所に配置します。
5. **そのほかすべて** の宛先を確認します。

エントリがないソースは何にも一致しません。グラフはノートもサポートしており、編集中に元に戻すややり直しも利用できます。

## 一致させることができるもの [#what-you-can-match]

| ソース | 一致内容 |
| --- | --- |
| **アプリケーション** | デスクトップ上のプロセス名、またはAndroid上のアプリ。 |
| **ドメイン** | サイトおよびサブドメイン。 |
| **IP / ネットワーク** | IPアドレスおよびCIDRブロック。 |
| **ドメインのパターン** | ドメイン正規表現。 |
| **ポート** | 単一のポートまたは範囲。 |
| **トラフィックのプロトコル** | HTTP、DNS、またはTLSのような検出されたトラフィック。 |
| **トランスポート** | TCPまたはUDP。 |
| **サービス / 国** | GeoSiteまたはGeoIPのカテゴリおよびルールセット。 |
| **ルールリスト** | ダウンロード可能なリストからのサイトまたはアドレス。 |
| **組み合わせ** | 複数の条件がANDまたはORで結合され、オプションでNOTを使用。 |

## 最初に一致したものが適用されます [#first-match-wins]

ルールは上から順にチェックされます。最初に一致したルールが経路を決定します。そのため、ドメインルールの前にアプリルールが経路を決定することができます。

たとえば、ほとんどのトラフィックをVPN経由で送信し、特定のアプリだけ直接送信する場合:

1. そのアプリのために **アプリケーション** ルールを追加し、 **直接** に接続します。
2. そのアプリにも一致する可能性のあるより広範なルールよりも上に配置します。
3. **そのほかすべて** を **VPN 経由** に接続します。

**ネットワーク接続** を使用して、どのルールがリクエストをキャッチしたかを確認します。ルールヒットの指標は、現在開いている一致する接続をカウントします。

## 特定のサーバーまたはDNSリゾルバ [#a-particular-server-or-dns-resolver]

別の出口を通すルールのために **特定のサーバー** を追加します。そのサーバーが後で削除された場合、ルールは接続されたサーバーにフォールバックします。

ドメイルールも独自のリゾルバを選択できます。割り当ての前に[DNS](/ja/docs/guides/dns)を参照してください。

## コアの互換性 [#core-compatibility]

内蔵コアは完全なルーティングエディタをサポートしています。Xrayはサーバートラフィックを処理し、内蔵コアはルーティングを保持します。mihomoを使用すると、検出されたプロトコルルールとsing-box形式ルールリストはスキップされ、独自の地理データが使用されます。[core differences](/ja/docs/reference/cores)を参照してください。

プリセット、GeoIP/GeoSiteデータ、共有、およびスケジュールについては、[ルーティング設定](/ja/docs/guides/routing-setups)を続けて使用してください。
