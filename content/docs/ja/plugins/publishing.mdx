## ビルド [#building]

```bash
go run ./cmd/nuggetplugin path/to/your-plugin
go run ./cmd/nuggetplugin path/to/your-plugin out/your-plugin.nuggetplugin
```

最初のコマンドはフォルダの横に `your-plugin.nuggetplugin` を書き込み、次のコマンドは出力に名前を付けます。どちらの場合も、プラグインをインストールした時と同じように正確にチェックし、要求された内容を表示します:

```
Glance 1.0.0: examples/plugins/glance.nuggetplugin (3 KB)
asks for: state, control
```

`.nuggetplugin` は普通のZIPファイルなので、任意のZIPツールで開けます。`plugin.json` がルートにあり、フォルダの中に入っていなければ問題ありません。インストールを確実に行うには、やはり`nuggetplugin` の方法が推奨されます。

## バージョンと更新 [#versions-and-updates]

既にインストールされているものと同じ `id` を持つプラグインをインストールすると、更新されます。

- ファイルが置き換えられます；
- ストレージは保持されます；
- 新しいバージョンで古いバージョンが持っていなかった権限を要求する場合は、インストールの確認画面でマークされ、ユーザーは再度許可する必要があります。

アプリはバージョンを比較しないため、古いバージョンをインストールすることも可能です。リリースごとに `version` を変更して、ユーザーがどのバージョンを持っているか分かるようにしてください。

`id` を変更してはいけません：新しいIDを持つプラグインは別のプラグインと見なされ、以前のストレージは引き継がれません。

## 共有 [#sharing]

`.nuggetplugin` ファイルを人々がダウンロードできる場所に置いてください：GitHub のリリース、あなたのウェブサイト、チャットなどです。プラグインはファイルからインストールされ、アプリが自動でダウンロードすることはありません。

プラグインの説明やホームページで、次のことを伝えてください：
- 何をするか；
- なぜ要求する各権限が必要なのか；
- どのホストに接続し、何を送信するか。

## チェックリスト [#checklist]

- [ ] `id` はあなたのものであり、永久的です。
- [ ] `version` は最新状態です。
- [ ] 使用するのは必要な権限のみ。
- [ ] `network` には接続するホストだけが記載されています。
- [ ] ページはライトテーマ、ダークテーマ、右から左の言語でも正しく表示されます。
- [ ] フォントや画像は再配布可能なものです。
- [ ] `go run ./cmd/nuggetplugin` は合格しています。
