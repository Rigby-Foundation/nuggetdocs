VPN クライアントはコンピュータが送信するすべてを確認できるため、プラグインは安全にインストールできるように作られています。プラグインはアプリに機能を追加できますが、ユーザーが許可した範囲を超えることはありません。

## 権限 [#permissions]

インストールのプロンプトには、プラグインが要求するすべての権限と、接続する可能性のあるすべてのホストが表示されます。追加の権限を求めるアップデートでは、新しい権限が表示され、再度確認を求められます。

| 権限 | プラグインに許可すること |
| --- | --- |
| `state` | VPN が稼働しているか、どのサーバーを通しているか、トラフィック（`vpn.status`、`vpn.traffic`およびそのイベント）を確認すること。 |
| `connections` | オープン接続を確認すること：サイト、プログラム、ルール（`connections.list`）。 |
| `profiles` | サーバーリストを確認すること：名前、プロトコル、ホスト名（`servers.list`）。認証情報を含むリンクは決して確認できません。 |
| `control` | サーバーに接続、切断、切り替えを行う (`vpn.connect`, `vpn.disconnect`)。 |
| `import` | サーバーとサブスクリプションを追加する (`servers.add`, `subscriptions.add`)。 |
| `routing` | ルーティングルールを追加する (`routing.addRule`)。 |
| `notifications` | システム通知を表示する (`notify`)。 |

権限がなくても、プラグインは自分のページを表示し、テーマを読み込み、アプリ内で短いメッセージを表示し、自分のストレージを使用することができます。

## サンドボックス [#the-sandbox]

ページは `allow-same-origin` なしでサンドボックス化されたフレーム内で実行されます。ページには独自のオリジンがないため、次のことにアクセスできません:

- アプリウィンドウやアプリの Go メソッド;
- 他のプラグインのページやストレージ;
- クッキー、`localStorage` または IndexedDB.

さらに、すべてのページには次を許可する Content-Security-Policy が適用されます:

- スクリプト、スタイル、画像、フォントはプラグイン自体（およびSDK）からのみ。インラインスクリプトとスタイルは問題ありません。
- ネットワーク接続は`network`のホストにのみ、`https`および`wss`経由で行うこと。
- フォーム、ネストされたフレーム、ワーカー、プラグイン（`<object>`）は禁止。

サンドボックスはポップアップ、ダイアログ、ダウンロード、アプリウィンドウのナビゲーションもブロックします。

ページはメッセージでのみアプリと通信できます。アプリはプラグインの権限に対してすべての呼び出しを確認し、何かを変更する場合はGoで再度確認します。

## プラグインが絶対にできないこと [#what-plugins-can-never-do]

- サーバーリンク、設定、ログ、またはディスク上のその他の情報を読み取ること。
- コアの設定を直接変更すること、またはネイティブコードを実行すること。
- このコンピュータまたはローカルネットワークにアクセスする: `localhost`、IPアドレスやローカル名は`network`にリストできません。
- トンネルを保持しているアプリの特権部分で何かを実行する。
- アプリとして自分を装う。トーストや通知には常にプラグインの名前が表示され、プラグインが追加したルールにはその旨の注意書きが付く。

## ユーザー向け [#for-users]

- **インストール前:** プラグインが何を要求しているか確認する。テーマは何も必要としない。ステータスウィジェットは`state`を必要とする。正当な理由なしに`routing`や`import`を要求するプラグインには注意する: `routing`はVPNの外にトラフィックを送信でき、`import`は他人が管理するサーバーを追加できる。
- **インストール後:** プラグインをオフにすると、そのページはすぐに停止します。削除すると、そのファイルとストレージは削除されますが、追加したルールはルーティングに残り、名前が付けられます。
