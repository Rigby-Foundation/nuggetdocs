## 小さなチェックから始めましょう [#start-with-a-small-check]

1. 通常のインターネット接続が機能することを確認してください。
2. プロバイダーのサブスクリプションが有効であることを確認し、更新してください。
3. 同じソースから別のサーバーを試してください。
4. **設定 → コア** を[互換性表](/ja/docs/reference/cores)と照合してください。
5. [ログ記録](/ja/docs/guides/monitoring#logs)をオンにし、エラーを再現して、障害メッセージを読みます。

## macOS はアプリが破損していると言っています [#macos-says-the-app-is-damaged]

macOS のビルドは Apple Developer 証明書で署名されたものではなく、臨時に署名されたものです。そのため、Gatekeeper がダウンロードしたアプリをブロックする可能性があります。

信頼できる公式リリースの場合、インストール済みアプリから隔離属性を削除してください：

```bash
xattr -cr /Applications/NuggetVPN.app
```

アプリを再度開いてください。このコマンドは、それを`/Applications`に置いたと仮定しています。

## デスクトップの許可プロンプトが失敗する [#the-desktop-permission-prompt-fails]

TUN インターフェースを作成するには管理者権限が必要です。アプリセッションの最初の接続時にシステムプロンプトを承認してください。Linux では、polkit と `pkexec` が利用可能であることを確認してください。

通常のユーザーとしてグラフィカルアプリを起動します。アプリは独自の特権サービスを起動します; グラフィカルインターフェースはrootとして実行する必要はありません。

## サブスクリプションをインポートできません [#a-subscription-will-not-import]

サブスクリプションのエンドポイントを貼り付けたか、プロバイダーのアカウントや支払いページを間違って貼り付けていないか確認してください。レスポンスにはサポートされている形式のサーバーデータが含まれている必要があります。

プロバイダーがクライアントの識別情報やデバイスIDを制限している場合、 **設定 → サブスクリプションの識別情報** およびプロバイダーの指示を確認してください。サポートを求める際にサブスクリプションURLを公開しないでください: アカウントのサーバーへのアクセス権を与える可能性があります。

## サーバーが別のコアを必要としていると言っています [#a-server-says-it-needs-another-core]

[コア互換性](/ja/docs/reference/cores)を使用してください。XHTTPは組み込みコアまたはXrayを必要とします；XrayはHysteria、Hysteria2、TUIC、またはSSHを実行できません。`rigby://`のプロファイルは、いかなる組み込みコアにも接続しません。

## 接続されましたが、ウェブサイトが読み込まれません [#connected-but-websites-do-not-load]

**ルーティング → そのほかすべて** およびルールの順序を確認してください。マッチするブロックルールはリクエストを停止することができ、ダイレクトルールはトンネルをバイパスできます。使用されたルールとサーバーを確認するには、 **ネットワーク接続** をチェックしてください。

次に、 **設定 → ホーム** の下のDNSおよびドメインルールに割り当てられた任意のDNSを確認してください。大きな転送が止まる場合は、MTUを低くして同じ転送を比較してみてください。

## 接続が切断された後、トラフィックがブロックされます [#traffic-is-blocked-after-a-connection-drops]

キルスイッチが有効になっている場合、予期しない停止時にブロックされることが想定されます。トンネルを復旧させるには再接続するか、意図的にブロックを解除するには **切断** を押してください。詳細は[キルスイッチの動作](/ja/docs/guides/connection#kill-switch)を参照してください。

## ルーティングルールは効果がありません [#a-routing-rule-has-no-effect]

空のルールは何にも一致しません。あなたの上にある広域ルールが先に一致する可能性があります。 **順序** を開き、順序を確認した後、新しい接続を生成して **ネットワーク接続** で確認してください。

mihomoを使用すると、検出プロトコルルールとsing-box形式のルールリストはスキップされます。削除された特定サーバー宛先は接続中のサーバーにフォールバックします。

## iOSはインストールされますが、決して接続されません [#ios-installs-but-never-connects]

署名証明書を確認してください。署名されていないIPAには、Network Extensionとパケットトンネルの権限が必要です。無料のApple IDで署名しても、必要な権限は付与されません。[iOS setup](/ja/docs/getting-started/mobile#ios) を参照してください。

## Wi-Fiの名前が非表示です [#wi-fi-name-is-hidden]

OSはSSIDを表示する前に位置情報の許可を求める場合があります。システムのプライバシー設定を確認するか、 **設定 → Wi-Fi** で信頼できるネットワーク名を手動で追加してください。

## ログには何もありません [#there-is-nothing-in-logs]

リリースビルドではデフォルトでログがオフになっています。 **ログ** または **設定 → プライバシー** で有効にし、問題を再現してから出力を確認してください。オフにすると保存されたログは削除されます。

## 再現可能な問題を報告してください [#report-a-reproducible-issue]

[GitHubの問題を使用してください](https://github.com/Rigby-Foundation/NuggetVPN/issues)。OS、アプリのバージョン、選択したコア、プロトコルとトランスポート、再現手順、および関連するエラーを含めてください。資格情報や接続の詳細を共有する前に、ログや設定抜粋を確認してください。
