## По умолчанию DNS [#default-dns]

**Настройки → Главная → DNS-сервер** управляет тем, где разрешаются имена во время подключения. Приложение принимает адрес резолвера, например `1.1.1.1`.

Имейте в виду требования вашего провайдера при изменении резолвера. Если сервер подключается, но веб-сайты не загружаются, DNS является одним из параметров, который следует проверить.

## DNS для правила [#dns-for-a-rule]

Доменные правила в **Маршрутизация** могут выбирать свой собственный DNS резолвер. Поле DNS правила принимает:

| Значение | Резолвер |
| --- | --- |
| `1.1.1.1` | Простой адрес сервера DNS. |
| `tls://dns.example.com` | DNS через TLS. Замените пример имени хоста на ваш резолвер. |
| `https://dns.example.com/dns-query` | DNS через HTTPS. Используйте фактическую конечную точку резолвера. |
| `local` | Локальное разрешение имен. |

Это управляет разрешением для соответствующих доменов. Назначение правила отдельно определяет, как будет маршрутизировано полученное соединение.

## MTU [#mtu]

**Настройки → Соединение → MTU** устанавливает наибольший пакет, передаваемый туннелем. Руководство приложения использует 9000 для большинства подключений и предлагает уменьшать его, когда крупные передачи зависают.

При диагностике проблемы изменяйте один параметр за раз и сравнивайте один и тот же запрос или передачу. Ведите запись предыдущего значения, чтобы можно было его восстановить.

## TLS и обфускация [#tls-and-obfuscation]

**Настройки → TLS и маскировка** включают TLS фрагментацию, смешанный регистр SNI, заполнение записей и подделку SNI. Эти параметры влияют на рукопожатия и должны выбираться в соответствии с известным сервером или требованиями сети.

Настройки фрагментации и SNI приложения TLS не применяются к mihomo или Xray. Для этих параметров используйте встроенное ядро или официальное sing-box. Смотрите [совместимость ядра](/ru/docs/reference/cores).
