## Типовий DNS [#default-dns]

**Налаштування → Головна → DNS-сервер** контролює, де розпізнаються імена під час підключення. Додаток приймає адресу резольвера, таку як `1.1.1.1`.

Майте на увазі вимоги вашого провайдера при зміні резольвера. Якщо сервер підключається, але вебсайти не завантажуються, DNS – одне з налаштувань, які слід перевірити.

## DNS для правила [#dns-for-a-rule]

Доменні правила в **Маршрутизація** можуть обирати власний DNS резольвер. Поле DNS правила приймає:

| Значення | Резольвер |
| --- | --- |
| `1.1.1.1` | Простa DNS адреса сервера. |
| `tls://dns.example.com` | DNS через TLS. Замініть приклад хостнейму на свій резольвер. |
| `https://dns.example.com/dns-query` | DNS через HTTPS. Використовуйте фактичну кінцеву точку резольвера. |
| `local` | Локальне визначення імен. |

Це контролює визначення імен для відповідних доменів. Призначення правила окремо визначає, як буде маршрутизовано результативне з’єднання.

## MTU [#mtu]

**Налаштування → З’єднання → MTU** встановлює найбільший пакет, що переноситься тунелем. Рекомендації додатку використовують значення 9000 для більшості каналів і пропонують зменшувати його, коли великі передачі даних зупиняються.

Під час діагностики проблеми змінюйте одну налаштування за раз і порівнюйте той самий запит або передачу. Зробіть нотатку попереднього значення, щоб мати змогу його відновити.

## TLS та обфускація [#tls-and-obfuscation]

**Налаштування → TLS і маскування** включає TLS фрагментацію, змішаний регістр SNI, заповнення записів та підробку SNI. Це впливає на рукостискання і повинно обиратися відповідно до відомого сервера або вимог мережі.

Налаштування фрагментації та SNI у додатку TLS не застосовуються до mihomo або Xray. Для цих контролів використовуйте вбудоване ядро або офіційний sing-box. Див. [сумісність ядра](/uk/docs/reference/cores).
