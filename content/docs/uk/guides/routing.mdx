title: "Маршрутизація трафіку"
description: "Виберіть, які додатки та сайти використовуватимуть VPN, підключатимуться напряму або блокуватимуться."
---

Відкрийте **Маршрутизація** , щоб створювати правила як граф або редагувати їх у вигляді правил. Правила співставляють з'єднання і направляють їх до призначення.

## Призначення [#destinations]

| Призначення | Поведінка |
| --- | --- |
| **Через VPN** | Використовує підключений сервер VPN. |
| **Напряму** | Обминає тунель і використовує ваше власне підключення. |
| **Блокувати** | Відхиляє з'єднання. |
| **Відкинути** | Відкидає з'єднання без відповіді. |
| **Конкретний сервер** | Надсилає відповідний трафік через інший налаштований сервер. |

<Callout type="warn" title="Прямий трафік обминає VPN">
Використовуйте **Напряму** тільки для трафіку, який ви хочете на власному з'єднанні. Також перевірте **Усе інше** : це визначає маршрут для трафіку, який не відповідає жодному правилу.
</Callout>

## Створити правило [#make-a-rule]

1. Відкрийте елементи керування **Додати** у **Маршрутизація** і оберіть джерело трафіку, наприклад, **Застосунки** або **Домени** .
2. Додайте додаток, домен, адресу або інші значення для відповідності.
3. У режимі графу тягніть від правого краю джерела до потрібного пункту призначення.
4. Відкрийте **Порядок** і розмістіть правило там, де його слід перевіряти.
5. Підтвердіть пункт призначення **Усе інше** .

Джерело без записів нічого не збігає. Граф також підтримує нотатки, а під час редагування доступні скасування та повторення дій.

## Що ви можете співставити [#what-you-can-match]

| Джерело | Відповідає |
| --- | --- |
| **Застосунки** | Назви процесів на робочому столі або додатки на Android. |
| **Домени** | Сайти та піддомени. |
| **IP / Мережі** | IP-адреси та CIDR-блоки. |
| **Шаблон домену** | Регулярні вирази для доменів. |
| **Порти** | Одиночний порт або діапазон. |
| **Протоколи трафіку** | Виявлений трафік, такий як HTTP, DNS або TLS. |
| **Транспорт** | TCP або UDP. |
| **Сервіс / Країна** | Категорії та набори правил GeoSite або GeoIP. |
| **Список правил** | Сайти або адреси зі списку, що можна завантажити. |
| **Складене** | Декілька умов, поєднаних через AND або OR, з можливим NOT. |

## Перше співпадіння перемагає [#first-match-wins]

Правила перевіряються зверху вниз. Перше правило, що підходить, визначає маршрут. Тому правило для додатку, розташоване вище за правило для домену, може визначити маршрут раніше, ніж буде розглянуте доменне правило.

Наприклад, щоб більшість трафіку йшло через VPN, але певний додаток підключався безпосередньо:

1. Додайте правило **Застосунки** для цього додатку та підключіть його до **Напряму** .
2. Тримайте це вище за загальні правила, що також можуть відповідати додатку.
3. Під’єднайте **Усе інше** до **Через VPN** .

Використовуйте **Мережеві з’єднання** , щоб перевірити, яке правило спрацювало на запит. Індикатор спрацьовування правила рахує відповідні з’єднання, що зараз відкриті.

## Конкретний сервер або DNSрезольвер [#a-particular-server-or-dns-resolver]

Додайте **Конкретний сервер** , щоб пропускати правило через інший вихід. Якщо той сервер буде видалений пізніше, правило повернеться до під’єднаного сервера.

Правило для домену також може обрати власний резольвер. Див. [DNS](/uk/docs/guides/dns) перед призначенням.

## Сумісність ядер [#core-compatibility]

Вбудований ядро підтримує повний редактор маршрутизації. Xray обробляє серверний трафік, тоді як вбудований ядро зберігає маршрутизацію. За допомогою mihomo правила з виявленими протоколами та списки правил у форматі sing-box пропускаються, і використовується власна геоінформація. Див. [різниці ядра](/uk/docs/reference/cores).

Для пресетів, даних GeoIP/GeoSite, спільного використання та розкладів продовжуйте з [налаштування маршрутизації](/uk/docs/guides/routing-setups).
