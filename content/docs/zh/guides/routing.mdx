打开 **路由** 来以图形方式建立规则或在规则视图中编辑它们。规则匹配连接并将其发送到目的地。

## 目的地 [#destinations]

| 目的地 | 行为 |
| --- | --- |
| **通过 VPN** | 使用已连接的 VPN 服务器。 |
| **直连** | 绕过隧道，使用您自己的连接。 |
| **阻止** | 拒绝连接。 |
| **丢弃** | 不作回应地丢弃连接。 |
| **指定服务器** | 通过另一个已配置的服务器发送匹配的流量。 |

<Callout type="warn" title="直接流量绕过 VPN">
仅对您希望通过自己连接的流量使用 **直连** 。也检查 **其他所有流量** ：它决定了与任何规则不匹配的流量的路径。
</Callout>

## 创建规则 [#make-a-rule]

1. 打开 **添加** 控件在 **路由** 中并选择流量来源，例如 **应用程序** 或 **域名** 。
2. 添加要匹配的应用程序、域名、地址或其他值。
3. 在图形视图中，从源的右边缘拖动到您想要的目标。
4. 打开 **顺序** 并将规则放在应检查的位置。
5. 确认 **其他所有流量** 的目标。

没有条目的源不匹配任何内容。图表也支持注释，并且在编辑时可以使用撤销和重做功能。

## 你可以匹配的内容 [#what-you-can-match]

| 来源 | 匹配 |
| --- | --- |
| **应用程序** | 桌面上的进程名称或Android上的应用程序。 |
| **域名** | 网站和子域。 |
| **IP / 网段** | IP地址和CIDR块。 |
| **域名模式** | 域名正则表达式。 |
| **端口** | 单个端口或范围。 |
| **流量协议** | 检测到的流量，例如 HTTP、DNS 或 TLS。 |
| **传输层** | TCP 或 UDP。 |
| **服务 / 国家** | GeoSite 或 GeoIP 的类别和规则集。 |
| **规则列表** | 可从可下载列表中获取的网站或地址。 |
| **组合** | 使用 AND 或 OR 连接的多个条件，可选择 NOT。 |

## 首个匹配优先 [#first-match-wins]

规则从上到下检查。第一个匹配的规则决定路由。因此，应用规则在域规则之上，可以在考虑域规则之前决定路由。

例如，要通过 VPN 发送大部分流量，但某个特定应用直接发送：

1. 为该应用添加 **应用程序** 规则，并将其连接到 **直连** 。
2. 将其置于可能也适用于该应用的更广泛规则之上。
3. 将 **其他所有流量** 连接到 **通过 VPN** 。

使用 **网络连接** 来检查哪个规则捕获了请求。规则触发指示器统计当前打开的匹配连接数。

## 特定的服务器或DNS解析器 [#a-particular-server-or-dns-resolver]

添加 **指定服务器** 以通过另一个出口发送规则。如果该服务器随后被删除，规则将回退到连接的服务器。

域规则也可以选择自己的解析器。在分配之前，请参见 [DNS](/zh/docs/guides/dns)。

## 内核兼容性 [#core-compatibility]

内置核心支持完整的路由编辑器。Xray 处理服务器流量，而内置核心保留路由功能。使用 mihomo 时，会跳过检测协议规则和 sing-box 格式的规则列表，并使用其自己的地理数据。请参阅 [核心差异](/zh/docs/reference/cores)。

对于预设、GeoIP/GeoSite 数据、共享和计划，请继续使用 [路由设置](/zh/docs/guides/routing-setups)。
